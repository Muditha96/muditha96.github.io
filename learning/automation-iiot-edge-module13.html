01 — Quick Understanding
CLIENT-SERVER
1-to-1
Classic OPC-UA: stateful session, full address-space model, security handshake per connection. Ideal for SCADA/MES talking to one specific machine.
PUBSUB
1-to-many
Decoupled — publishers emit DataSetMessages; subscribers receive via UDP or an MQTT broker. Perfect for fan-out telemetry to cloud/analytics/digital twins.
TRAFFIC REDUCTION
~30×
2,000 tags polled at 10 Hz = 20,000 msg/s. Subscription-based reporting on change ≈ 600 msg/s worst case.
SPARKPLUG B
B/D
Standardises MQTT topic namespace (spBv1.0/…), payload encoding, and state via Birth/Death certificates — makes MQTT data self-describing.

06 — Engineering Tips
1
Subscribe, Don't Poll
Use Subscribe + MonitoredItems with a sensible deadband (e.g. ±0.5%) instead of cyclic Read. This is the single biggest lever for cutting network load — the 20,000 → 600 msg/s example is not a worst case, it's typical.
2
Adopt Sparkplug B for MQTT, Not Raw JSON
Raw MQTT topics are not self-describing — every consumer needs custom mapping. Sparkplug B's NBIRTH/DBIRTH messages publish the full metric schema once, so any compliant subscriber can auto-discover tags without configuration.
3
Use Birth/Death Certificates for State
An NDEATH message (sent via MQTT Last Will & Testament) tells the broker — and every subscriber — that an edge node went offline, without waiting for a timeout. Dashboards should treat missing NDEATH as a stale-data flag.
4
Keep One Registered Port: 4840
OPC-UA's opc.tcp://host:4840 replaces the dozens of dynamic ports OPC Classic/DCOM required. When opening firewalls for plant-to-IT traffic, this single port (plus MQTT's 8883 for TLS) is usually all that's needed.
5
Edge Gateway = Protocol Translator + Buffer
Position the edge gateway to read legacy field protocols (Modbus, profile-specific fieldbuses), republish as OPC-UA/MQTT, and buffer DataSetMessages locally during cloud connectivity loss — replay on reconnect.
6
Enforce SignAndEncrypt End-to-End
Never run production OPC-UA with SecurityMode = None or anonymous Sessions. Pair with MQTT TLS (port 8883) so the entire path from sensor to cloud is encrypted and auditable per IEC 62443.
07 — Common Failures
📡Message Storm from Polling
Network saturates after adding tags. Cause: Client uses Read service in a tight loop instead of Subscribe. Fix: Convert to MonitoredItems with deadband filtering — typically cuts traffic by 20–30×.
👻Stale Data Looks "Live"
Dashboard shows last-known value after edge node loses power. Cause: No NDEATH/LWT configured on the MQTT client. Fix: Configure MQTT Last Will & Testament to publish NDEATH immediately on disconnect.
🔓Anonymous OPC-UA in Production
Unauthorized client reads/writes process tags. Cause: SecurityMode left at None, anonymous Sessions enabled "for testing." Fix: Enforce SignAndEncrypt + certificate-based Activate Session before go-live.
🧩Every Integrator Maps Tags Differently
Each new SCADA/cloud connection needs a custom tag-mapping spreadsheet. Cause: Raw MQTT topics with no agreed schema. Fix: Adopt Sparkplug B so NBIRTH/DBIRTH self-describe every metric.
🔌Lost Data During Network Outage
Gap appears in cloud historian after a WAN blip. Cause: Edge gateway has no local buffer; publishes drop silently. Fix: Enable store-and-forward buffering on the edge gateway with replay on reconnect.
🐌Cloud Latency Breaks a Control Loop
Operator notices delayed valve response after "moving logic to the cloud." Cause: Real-time control placed on a cloud round trip (50–200 ms+). Fix: Keep control loops on the PLC/edge; cloud only consumes telemetry, never closes the loop.
08 — Pro Engineer Notes
⭐ Real Industrial Example
A multi-vendor plant connects 200+ machines via OPC-UA at the edge, republishes through PubSub-over-MQTT with Sparkplug B, and feeds a cloud digital twin built on companion specs (OPC UA for Machinery). No custom drivers per machine — the companion spec IS the integration contract.
⭐ Classic vs PubSub Is Not Either/Or
Keep client-server for engineering/diagnostic access (Browse, Call methods like Calibrate) and add a PubSub publisher on the same OPC-UA server for telemetry fan-out. Most modern stacks (e.g. asyncua, open62541) support both simultaneously.
⭐ Sizing the MQTT Broker
At ~600 msg/s for 2,000 tags, a single broker instance handles this easily — but plan for fan-out multiplier: each subscriber (historian, dashboard, ML pipeline) receives its own copy. Broker throughput = publish rate × subscriber count.
⭐ Memory Hook
"OPC-UA describes the data. MQTT moves the data. Sparkplug B makes both speak the same language." Edge handles control and translation; cloud handles scale, history, and digital twins.
